# M9 — lighting

date: 2026-07-21

## what got added

- light nibbles per voxel (low = block, high = sky) stored on Chunk as atomic bytes —
  relaxed atomics are plain MOVs on x86, so mesh workers can read while the main-thread
  BFS writes, formally race-free and free of cost. arrays are lazy: uniform-lit chunks
  (all sky, all dark) store one byte. the array survives pool reuse.
- `light/LightEngine`: all propagation on the main thread through explicit BFS queues
  under a time budget (light is memory-bound pointer chasing, misery to parallelize;
  budgeted-incremental can't stall a frame). deviation from the spec's "light as a
  worker pipeline stage" — documented and argued: single writer, no atomics in the
  engine itself, and the same code path serves world load and block edits.
- sky: seeded per chunk-column (all 4 chunks at once, direct pointers, uniform-air fast
  path), full strength straight down, attenuate-by-1 in every other direction. spread
  sources = direct-sky voxels bordering shadowed air, which pure heightmap terrain has
  none of — caves get lit through their mouths when M10 adds them.
- removal: its own BFS. everything the removed source fed gets zeroed and re-queued as
  removals; still-lit boundary voxels become re-propagation seeds. verified by test.
- meshes bake light: the face's air-voxel light joins the greedy merge key (spec rule),
  packs into the quad's reserved 8 bits, shader applies a smoothstep brightness curve
  that is exactly 1.0 at full light. light changes mark chunks touched -> back through
  the normal remesh pipeline (old arena range freed on re-upload).
- glow block (id 4, luminance 14) + a deterministic enclosed test room in the terrain.

## verification

- room sky = 0 (enclosed), one-above-glow = 13, gradient 8 at distance, surface sky = 15
- remove glow -> light collapses to exactly 0; re-add -> exactly restored. PASS both.
- above-ground smoke image still byte-identical (773,776 px): full daylight multiplies
  by exactly 1.0, so lighting provably changed nothing it shouldn't have.
- glow room screenshot shows the per-quad gradient (flat per face — the 64-bit quad
  format ruling; per-corner smooth light means widening to 96/128-bit quads later).

## costs

- mesh avg 0.19 ms (light sampling + connectivity included), workers.
- worst main-thread update during full re-stream: 5.0 ms (was 0.94) — column light
  seeding at ~0.5-1 ms each, capped at 3/frame, plus 1.5 ms of BFS budget. only during
  burst streaming; steady state unchanged at ~0. future work if it matters: move column
  seeding into a worker light stage with column ownership.
