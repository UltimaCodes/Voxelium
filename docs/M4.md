# M4 — binary greedy meshing + vertex pulling

date: 2026-07-21

## what got added

- `mesh/QuadFormat.hpp`: one quad = one uint64. lo word: x/y/z origin (5b each),
  w-1/h-1 (5b), dir (3b). hi word: block (12b), ao (8b, M9), light (8b, M9). no field
  crosses the 32-bit line so the shader reads a uvec2 without stitching. 8 spare bits.
- `mesh/GreedyMesher`: three passes.
  1. solidity columns — one uint64 per (axis, row), voxel i at bit i+1, bits 0/33 are
     the neighbor pad (air until M5 wires real neighbors)
  2. face masks: `col & ~(col >> 1)` / `col & ~(col << 1)` does all 32 voxels of a
     column in two ops. set bits scatter into per-(dir, slice, block) 32x32 bit planes —
     block is the merge key, AO + light join it in M9
  3. greedy merge: countr_zero/countr_one find the lowest run, extend down while rows
     contain the same span, clear bits, emit packed quad
  scratch lives in the mesher instance (reused, no allocs when warm). one instance per
  worker thread when M6 lands.
- vertex pulling: no VBO, no vertex attributes, an empty VAO. quads sit in an SSBO,
  chunk.vert unpacks gl_VertexID/6 and reconstructs corners from per-dir tables (same
  CCW winding as the naive mesher, backface culling unchanged).
- naive mesher stays as the oracle: summed quad area per direction must exactly equal
  naive's per-direction face counts. checked at startup, all 6 match.
- t-junction cracks: greedy quads leave sub-pixel holes where a quad corner sits mid-edge
  of a bigger neighbor (interpolation never exactly hits the transformed corner — no
  vertex math fixes that). found 2 actual pinhole pixels in the smoke image. fix: bloat
  every quad 0.001 in-plane so neighbors overlap sub-pixel. coplanar overlap is
  invisible; holes are not.

## before/after, same test chunk as M3

| metric | naive (M3) | greedy (M4) | factor |
|---|---|---|---|
| tris | 13,120 | 4,808 | 2.7x fewer |
| geometry memory | 615 KB (96 B/face) | 18.8 KB (8 B/quad) | 33x less |
| mesh time (best of 50) | 0.195 ms | 0.057 ms | 3.4x faster |
| gpu format | vbo, 16 B verts | ssbo, uint64 quads | — |

the mesher got faster while doing more — bit ops replace per-voxel neighbor lookups.
0.057 ms is 17x under the 1 ms budget, and that's before palette-aware fast paths
(uniform chunks skip meshing entirely in M5).

note: 2.7x tris on this terrain is honest but unflattering — the sine hills are stepped
so top faces merge into contour bands, not giant slabs. flat/uniform regions (most of a
real world) merge far better; re-measure at M5/M10 with real terrain.

smoke coverage 283,782 px vs naive's 283,778 — pixel-equivalent render (diff is the
sub-pixel bloat). heap allocs/frame still 0.
