# M3 — one chunk, dumb mesh (THE baseline)

date: 2026-07-20

## what got added

- `world/Chunk`: 32^3, flat uint16 array (64 KB). indexing is `x | z<<5 | y<<10` — pure
  shifts, power-of-two size is why. palette compression comes in M5, the mesher only
  touches get() so storage can swap out under it.
- `mesh/NaiveMesher`: the deliberately dumb baseline. walks every voxel, emits 6 expanded
  verts (16 B each) per face that borders air, no index buffer, no merging. hidden-face
  culling is the only smarts: solid-solid faces are skipped, chunk border counts as air
  until M5 wires neighbors.
- deterministic test terrain: sine heightfield (grass/dirt/stone) + a carved air pocket
  under the surface. cavity walls MUST appear in the face count, the solid interior must
  not — that's the correctness check. M4 meshes the exact same data.
- chunk shader: face shade baked into vertex color at mesh time (top 1.0, x-sides 0.8,
  z-sides 0.65, bottom 0.5). backface culling on, mesher winds CCW from outside.
- vsync now OFF by default (toggle in HUD). everything time-based runs off dt / absolute
  time, so uncapped fps never changes game speed.

## baseline numbers (gcc 16.1 -O3, ryzen-side of the 2070S box)

test chunk = sine heightfield + cavity, ~17.7k solid voxels:

| metric | naive |
|---|---|
| faces / tris / verts | 6,560 / 13,120 / 39,360 |
| vbo size | 615 KB (16 B/vert, expanded) |
| mesh time (50 runs) | best 0.198 ms, avg ~0.23 ms |
| draw calls | 1 |

heap allocs/frame still 0. smoke covers 30.8% of 1280x720, deterministic.

M4 has to beat: 13,120 tris and 615 KB for this chunk. greedy merging on flat-ish sine
terrain should collapse most of the top surface into big quads, and the packed format is
8 B per QUAD vs 96 B per face here (6 verts x 16 B) — expecting roughly an order of
magnitude on both. mesh time target stays < 1 ms.
