# M12 — persistence

date: 2026-07-22

## what got built

- `io/ChunkSerializer`: chunk <-> bytes as run-length over the block grid in index
  order. voxel data is dominated by runs (air columns, stone layers), so RLE crushes it
  with zero external dependency — a generated cave chunk goes 65536 B raw -> 5740 B
  (11x), a uniform chunk is ~4 bytes. counts/ids are LEB128 varints. light is NOT
  stored: it re-seeds through the normal pipeline on load, so the loader is identical to
  gen and the format is pure content.
- `io/RegionStore`: region files group 16x16 columns (all kWorldChunksY tall) into one
  `r.<x>.<z>.vxr` file so the world isn't a swarm of tiny files. header + directory
  (offset/length per slot) + concatenated blobs. regions held in memory once touched,
  written back on flush. writes go to a temp file + rename so a crash mid-write can't
  corrupt a region. thread-safe (one mutex): worker gen jobs read through load() while
  the main thread writes through save()/flush().
- **only edited chunks are saved.** unedited terrain regenerates deterministically from
  the seed, so the save format stores just the player's diffs from procedural gen —
  minimal disk, and the world is reproducible. setBlock marks its chunk dirty; dirty
  chunks serialize on eviction and on save. F2 saves, and it saves on exit.
- disk-first generation: the gen job calls regions.load(pos) first (on the worker, no
  main-thread I/O) and only falls back to m_gen.generate() if the chunk wasn't saved.

## verification (all in --smoke)

- serialize round-trip: every voxel of a generated cave chunk matches after
  serialize -> bytes -> deserialize. PASS.
- edit -> saveDirty -> load the region blob into a FRESH chunk: the edited block is
  present. PASS.
- **end-to-end**: edit a block, save, fly 4096 blocks away (evicting the chunk), fly
  back — the chunk regenerates FROM DISK (not the seed) with the edit intact. PASS.
  this is the real feature: player changes survive unload/reload.
- 2 chunks / 5.1 KB on disk after the test edits.

## bug found and fixed along the way (important)

the debug build's container assertions caught a **data race that release was silently
tolerating**: LightEngine::seedColumn reads a column's 4 horizontal neighbors, and one
could be mid-generation on a worker. generate() calls makeUniform, whose clear() ->
push_back() leaves the palette momentarily empty (size 0); the main-thread light read
hit palette[0] out of bounds. release read torn data instead of crashing. fix: gate a
column's light seed on its 5-column (self + 4 ortho) neighborhood being non-Generating,
matching the guard the mesh scheduler already had. absent neighbors are fine (blockAt
treats them as stone); only in-flight generations block, and the column retries once
they settle. this is why the debug build is worth running even when release "works".

## final pipeline cost (RTX 2070S, 1280x720, radius 10, everything on)

full frame 5.02 ms (shadows 4.87 dominate, ssao/volumetric/bloom ~0.2 each). shaders
off: ~0.9 ms. heap allocs/frame 0 in steady state.
