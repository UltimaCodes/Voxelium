# Milestone 1 — Window + GL context + spinning triangle

Date: 2026-07-20
Machine: NVIDIA GeForce RTX 2070 SUPER, driver 596.21, GL 4.6.0 core
Toolchain verified: GCC 16.1 (WinLibs MinGW-w64, UCRT, posix threads) + Ninja, CMake 4.3.2
MSVC: preset exists (`--preset msvc`) but Visual Studio is not installed on this machine —
unverified until VS Build Tools are available.

## What exists

- GLFW 3.4 window + OpenGL 4.6 core context. Debug context in Debug builds and `--smoke` runs.
- glad2-generated loader, 4.6 core, zero extensions (everything needed is core in 4.6).
  Vendored; regeneration command in `external/glad/README.md`.
- KHR_debug callback installed from day one (`gfx/GlDebug`). Synchronous in Debug so a
  breakpoint in the callback lands on the offending GL call. Full logger/HUD routing is M2.
- Shader loading from `assets/shaders/` with explicit `layout(location=N)` attributes and
  uniforms — no `glGetUniformLocation` string lookups anywhere, ever.
- DSA-only object creation: `glCreateBuffers` + `glNamedBufferStorage` (immutable),
  `glVertexArray*` attribute setup. No bind-to-edit.
- `--smoke [out.bmp]`: renders to an offscreen FBO, verifies pixel coverage, writes a BMP,
  exits 0/1. Offscreen because reading a hidden window's default framebuffer fails the
  pixel-ownership test. This is the headless self-check for every future milestone.

## Decisions

- **Immutable buffer storage everywhere.** `glNamedBufferData` allows resize, which makes
  drivers defensive; `glNamedBufferStorage` is fixed-size and is the only storage kind
  that supports persistent mapping (needed for the M7 quad arena). Adopt it on day one.
- **Explicit attribute/uniform locations** so the CPU↔shader interface is a compile-time
  contract, not a runtime string lookup.
- **assets/ found by walking up from the exe** — the binary runs from any build tree
  without working-directory setup.
- **vsync on by default**; real frame timing arrives with the M2 HUD.
- The triangle's VAO/VBO path is throwaway — from M4 on there are no vertex attributes at
  all (SSBO vertex pulling).

## Numbers (baseline)

- Smoke test: 52,469 / 480,000 pixels covered (10.9%) at 800×600 — deterministic image.
- Windowed run: stable at vsync (title bar shows ms/frame); ESC to close.
- Build: warning-clean under `-Wall -Wextra -Wpedantic -Werror` (GCC 16.1), Debug + Release.
- Known/expected: NVIDIA perf message "Pixel transfer is synchronized with 3D rendering"
  during smoke readback — glReadPixels is a sync point by design; smoke path only.
